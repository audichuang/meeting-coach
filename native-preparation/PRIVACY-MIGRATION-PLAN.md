# 聲紋資料遷移與刪除策略（草案）

本文件是設計，尚未執行遷移、掃描、匯出或刪除任何既有私人資料。執行前需確認 Audi 與公司政策、備份／保留規定、還原能力、受影響資料及明確使用者選擇；不要以升級為由靜默清除。

## 既有資料盤點

- 來源：SwiftData `Recording.speakerVoiceprintsData`、`Speaker.voiceprintData`、舊 schema、任何版本化備份／測試或診斷副本、匯出、臨時檔和未來雲端系統。以固定版本程式和 migration 審查每個實際位置，不因欄位名就假設只存在主資料庫。
- 逐字稿、匿名標籤和音訊分開列管；刪聲紋不應刪原音、逐字稿或人工姓名。人工身份與聲紋為不同權限範圍。
- 開發階段先用全合成的多版本 SwiftData store 建立 migration fixtures：空值／舊 schema／含姓名與向量／多段會議／損壞或中斷。不得用真實資料當 fixture。

## 執行方案（待審核）

1. 提示影響範圍及本機、備份、已匯出／已傳服務的限制；記錄使用者的選擇和政策版本。不把一般升級或錄音同意視為聲紋同意。
2. 停止處理、建立經驗證且受保護的可恢復備份，先做容量和可寫檢查；備份本身含敏感資料，必須有明確存取、保留及刪除策略。不要複製不一致的活動 SQLite/WAL 組合，使用資料庫支援的安全備份／快照方法。
3. 透過版本化 SwiftData migration 或明確的資料服務，在交易中清除所有目標欄位並記錄最少量完成狀態；不儲存向量、姓名、逐字稿或音訊至日誌。為避免資料遺失，錯誤時停止並保留可復原狀態，允許安全重試。
4. 新版本禁止未同意的儲存、跨會議比對和身份呈現；將來有同意功能時需粒度、可撤回、刪除衍生特徵與回溯可追蹤審核，另行設計。
5. 重新開啟合成 fixture 驗證目標欄位均清空、原音／轉寫／匿名分段仍可讀、升級中斷可恢復、重跑具冪等性；同時測試多版本與失敗注入。針對資料庫 freelist、WAL、備份、快取與檔案保護另作威脅模型；不能聲稱 SQLite 刪值立刻使所有底層位元組不可復原。
6. 依保留政策排程並確認本機備份、受控雲端或其他已知副本的刪除／到期；已由使用者匯出或送往第三方的資料需明示無法由本機直接撤回。刪除確認以可核實的來源逐項回報，避免承諾完全抹除。

## 建議事件持久化整合點

`KurnCore/SuggestionEvents.swift` 為純 Swift domain，沒有 SwiftData、UI、網路、模型密鑰或實際會議資料。App 整合應新增版本化儲存實體；候選及 `.created` 在**同一原子交易**先保存，再執行 gate；即使 `.suppressed` 或使用者 `.dismissed` 仍以 append-only 事件保存。以 UUID、事件相對時間、UTC、證據範圍／逐字稿 revision、版本和簡明原因追溯；重新載入以 `SuggestionLedger(restoring:)` 檢查順序。事件與候選在 meeting 刪除時依政策級聯處理；model/prompt 版本標籤不含秘密。AI 與使用者輸入皆不可信，顯示前驗證，不能保存私有思維鏈。
