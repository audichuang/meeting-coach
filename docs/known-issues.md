# 已知未處理

審查找到、評估後暫不修的問題。機率低或屬於 Kurn 原有行為；之後若要處理，建議整體設計一個「依會議／錄音登記並取消所有 AI 工作」的機制，而不是逐條補。

## 刪除與取消
- 錄音剛結束、教練工作還在收尾時刪除那場會議或錄音，收尾中的建議卡或摘要請求可能仍送出一次，並嘗試寫入已刪除的資料。
- 會後摘要進行中刪除其中一段錄音，摘要不會取消，可能仍包含那段內容。
- 正常收尾的 8 秒內觸發預算停止，即時轉寫連線要等收尾逾時才關。
- 「刪除所有資料」不取消 Kurn 原有的轉錄後 AI 工作（AI 標題、Wiki）。

## 其他
- 同一場會議的教練摘要偶爾會多跑一次（出列與讀取逐字稿之間的競態）。
- 即時逐字稿在斷線中停止錄音時，尾端約 2 秒可能沒算進缺口；正式逐字稿會補回。
- 背景排程以一般轉錄設定判斷能否在背景恢復教練錄音，可能要等使用者開啟 App 才恢復。
- 逐字稿存檔失敗時不回滾狀態；機率極低，畫面會顯示錯誤，可手動重轉。
- 轉寫連線還在但伺服器端轉寫失敗時，畫面仍顯示 Live；結束時會補標缺口。
- Worker 的月上限不是原子預扣，同時多個請求可能略為超支；即時轉寫的費用是估算，月上限對它不是硬上限。

## 手寫紙面
- 筆跡存檔在背景執行，與停止、刪除之間有時間差。三種情況會掉資料，都要存檔失敗或在一秒內操作才會碰到：停止錄音的瞬間存檔失敗，停止前不到一秒的筆跡可能沒存；停止後一秒內刪掉那段錄音，筆記卡可能留在會議裡刪不掉；存檔失敗後重試成功，兩段筆跡的時間錨點會合併成一個。

## 本人標記
- 停止錄音時剛好碰上講者分離在補缺口，最後幾段的講者標籤可能標錯。
- 缺口超過 30 秒或模型出錯時，這場會議停掉即時講者分離，之後的段落沒有標籤，畫面不提示已停止。
- 模型下載中斷可能顯示已安裝但無法使用，到設定刪掉再下載即可。改標記的那幾秒內送出的建議卡可能用舊身份。
- 模擬器要強制 CPU 才分得出講者；真 iPad 用 Neural Engine 的結果未驗證。
